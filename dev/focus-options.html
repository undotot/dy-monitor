算法与实现边界

现有代码：先选择共同比例 → 枚举右侧数量与两区列数 → 求统一小窗宽度 → 以观看尺寸、主容器面积和视频面积评分。混合比例的 contain 黑边仍存在，主窗容器黑边也会参与原有布局面积评分。

新版评分：主窗容器不限视频比例，观看目标 640×360；小视频短边目标 112.5px；主窗容器面积至少为最大小窗的 1.5 倍。A / B / C 在观看尺寸达成率相同时最大化布局占屏，不再要求主视频达到 640×360。

D：枚举原顺序的连续分组，比较整列、整行与双分区。3–4 格不再强制双分区；5–16 格在观看尺寸相近时优先两侧都有小窗，比例与墙面方向不合时允许单分区铺满。只有完全不存在满足边界、比例与主窗面积的贴边候选才保留空位。观看尺寸是软目标，不能用它否决全部可行的铺满结构。

2 格边界：当唯一小窗比例与整墙相同时，两个矩形无法同时满足铺满、小窗完整无黑边、主窗面积更大。此条件会如实显示空位。3、4 格不会沿用此前强制双分区造成的空位。

正式接入范围：布局纯函数、每格几何设置、ResizeObserver / loadedmetadata 触发及布局测试。继续复用播放器节点，视频 contain、标题与控制栏覆盖在画面上；接口、后端、数据库均无需修改。预览不验证真实视频流。
