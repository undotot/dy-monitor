# 监控室 UI 方案：桌面与 iPad 共用交互

设计日期：2026-10-16。依据当前 `src/` 的真实实现，尤其是已落地的综合均衡放大布局。本文件为待评审设计，不改变现有业务代码。

## 1. 推荐方案

采用“画墙观看、固定区域操作当前房间、公共面板管理内容”的结构。桌面和触屏共用功能、命令和状态；窗口宽度决定排版，输入能力决定命中区和快捷交互。

画墙内保留主播名、直播状态、出声提示和必要的错误重试，不在每个小窗内安排整排工具条。点击/轻点只选中房间；固定控制条显示当前操作对象及其动作。桌面双击、右键和拖动保留为快捷入口，每项功能都有可点击、可轻点的等价路径。

## 2. 当前代码中的具体问题

| 现状 | 依据 | 设计处理 |
| --- | --- | --- |
| 画格工具按钮 26×26px、声音按钮 24×24px，声音角标还会缩放 | `ui/styles.css`、`core/tile-scale.js` | 触控命中区至少 44×44 CSSpx，核心操作采用 48×48；小窗变小只减少入口，保持按钮尺寸 |
| 选中唤出工具条后 3.5 秒自动隐藏 | `app/tile-events.js` | 触屏选中的房间由固定控制条操作；菜单、滑杆和表单交互期间不自动关闭 |
| 放大主要依赖双击或右键；单房工具条缺少直接放大入口 | `app/tile-events.js`、`app/context-menu.js`、`ui/tile-markup.js` | 固定提供“放大 / 恢复平铺”，桌面双击作为快捷入口 |
| 整个画格设为 draggable，交换主要依赖原生拖拽 | `app/tile-drag.js` | 桌面从专用手柄拖动；两端均提供“调整位置 → 点源房间 → 点目标房间” |
| 声音图标第一次点击展开，第二次点击切换静音 | `app/tile-audio.js` | 静音按钮一次操作即生效；独立声音面板负责音量调节 |
| 独奏目标默认跟随 selectedId，选中另一个房间可能改变声音 | `app/audio.js`、`app/layout.js` | 操作房间、放大房间、听音房间分别记录，选中不会隐式切换声音 |
| 单房弹幕侧栏占用画格内部宽度 | `ui/tile-markup.js`、`ui/styles.css` | 弹幕列表进入公共面板，维持视频画格的原比例 |
| 顶栏聚集声音、增益、布局、弹幕、批量播放、添加和退出；折叠把手只有 18px 高 | `ui/shell-markup.js`、`ui/styles.css` | 顶栏只留常用全局入口；设置及低频操作进入面板；触屏恢复入口保持可点 |
| 布局标为 1×1、2×2 等，实际 layoutMode 表示列数 | `ui/shell-markup.js`、`app/layout.js` | 显示为“自动 / 1列 / 2列 / 3列 / 4列”；平铺与放大模式分别说明 |
| 弹幕画中画只实现 Document Picture-in-Picture | `playback/pip.js` | 按真实能力展示“弹幕画中画”，不把系统视频画中画当成已有功能 |

## 3. 界面分区

```text
┌ 监控室 · 8/16房间   [房间] [平铺/放大] [声音] [设置] [更多] ┐
│                                                        │
│                   原比例视频画墙                         │
│             主窗 + 全局等大小窗 / 普通平铺                │
│                                                        │
├ 主播A · 播放中 · 正在出声                                ┤
└ [暂停] [静音] [仅听此房] [放大] [弹幕] [音量] [更多]        ┘
```

### 顶栏

- 常驻：房间数与播放概况、房间、显示模式、声音、设置、更多。
- “房间”面板统一容纳已添加、关注、历史和现有团播入口；搜索框接受房号、链接或主播名。
- 播放管理收进“更多”：开始/继续全部、停止全部、重试异常。`ctx.stop` 会释放连接，因此继续使用“停止”，不改成含义不同的“暂停”。
- “设置”分为播放、声音与提醒、弹幕默认、工作区、诊断；版本和更新置于设置的关于区域。
- 退出监看与清空房间放在更多内，文案明确其影响。关闭一个面板不会退出监看或停止播放。
- 收起界面为显式“简洁观看”操作；桌面保留边缘快捷唤起，触屏常驻 48px 的“控制”恢复入口。

### 画墙

- 持续使用当前综合均衡算法和全部房间同屏的规则。
- 点击、轻点只修改当前操作房间；悬停不选中。
- 选中提示采用名称底板/顶部短线覆盖层，不新增改变画格尺寸的边框、间距或内边距。
- 小窗只呈现简洁名称及状态。完整名称、直播状态、播放状态和声音状态在控制条中展示。
- 触屏不要求在很小的画格上点多个角标；点击画面即可通过控制条操作。
- 桌面的大画格可悬停显示静音、放大、更多三个快捷动作，直接复用同一组命令。

### 当前房间控制条

- 固定在画墙外，不随单个视频缩小；始终写明主播名，避免操作错对象。
- 主操作：播放/暂停、静音、仅听此房、放大/恢复平铺、弹幕、声音调节、更多。
- 更多：画质、重新取流、停止连接、弹幕设置、替换房间、调整位置、支持的画中画/全屏、移除。
- 无房间选中时显示“选择一个房间进行操作”，保留相同高度，避免选择时画墙突然重排。
- 在 768px 以下采用“房间信息一行 + 五个核心按钮一行”：播放、静音、放大、弹幕、更多。仅听和音量进入声音面板。
- 操作时不隐藏；底部必须避开系统安全区域。声音滑杆区域至少 44px 高，并提供 ±5% 按钮或可点击刻度作为拖动替代。

### 公共面板

房间、声音、弹幕、设置使用同一个面板宿主，每次只打开一个主要面板。弹幕设置显式区分“当前房间”与“全局默认/批量应用”，每次批量应用都说明影响范围。

弹幕列表从单个画格内部移到公共面板。较宽窗口允许用户固定在侧边，此时画墙以剩余容器宽高重新求解；覆盖式面板保持画墙尺寸。两种方式均不会从某一个视频画格内部切走一块空间。

## 4. 桌面与触屏交互契约

| 操作 | 鼠标/键盘 | iPad 触屏 |
| --- | --- | --- |
| 选择房间 | 单击；标准按钮可用键盘激活 | 轻点视频 |
| 放大 | 控制条按钮；双击为快捷方式 | 控制条“放大” |
| 静音 | 一次点击即生效 | 一次轻点即生效 |
| 调音量 | 声音面板滑杆；滚轮为附加方式 | 大滑杆、刻度和 ±5% 按钮 |
| 更多操作 | 更多按钮；右键为同源快捷菜单 | 更多按钮打开操作面板 |
| 换位 | 专用手柄拖动；也支持两次点击 | 调整位置后点源、点目标；有取消按钮 |
| 关闭面板 | 显式关闭按钮；点击合适的外部区域 | 48px 关闭按钮；点遮罩关闭可取消面板 |
| 简洁观看后恢复 | 控制按钮、边缘唤起 | 可见的“控制”按钮 |

不以长按、双击或拖动作为触屏上的唯一入口。滑杆操作与换位状态隔离；收到 pointercancel 时取消交互，不执行延迟的选择、静音或交换。遮罩关闭的一次轻点不能继续触发其下方的视频。

保留当前关闭全局快捷键和 Esc 退出的产品决定；每个弹层都有可直接操作的关闭按钮。组件已有的 Tab、按钮激活及菜单方向键导航继续支持。

## 5. 关键状态必须分开

```text
selectedId       当前操作对象：切换控制条内容
focused          当前大窗：触发布局重算
audio.soloRoomId  当前仅听对象：决定声音路由
ui.panel         当前主要面板及其作用范围
ui.arranging     换位状态及源房间
ui.modal         当前确认或不可穿透的编辑流程
```

默认规则：

1. 仅听 A 时选择 B，不切换声音；放大 B，也不会在未启用“声音跟随大窗”时切换声音。
2. 点“仅听此房”明确设置听音对象并开启该房间声音；保留用户音量。音量为零时显示原因并提供调节，不暗中升高音量。
3. 取消仅听恢复进入前的全局声音模式；全局静音不覆盖各房间的音量和静音偏好。
4. 移除仅听对象后切为全部静音并提示选择新听音对象，避免意外让其他房间同时出声。
5. 控制条和右键菜单显式传入 roomId，不依赖“当前选中”在异步期间保持不变。
6. 非模态的当前房间面板随选中房间更新，标题同步刷新；替换房间、输入表单等明确绑定目标房间，保留草稿，不把输入内容应用给另一个房间。

## 6. 响应式规则

窗口排版与输入密度是两个独立维度。iPad 接鼠标后仍保留舒适命中区；窄桌面窗口也使用紧凑排版。以监控室实际容器 CSS 宽度判断，不使用物理分辨率或 User-Agent 作为主要依据。

| 可用宽度 | 排版 |
| --- | --- |
| ≥1280px | 一行顶栏和控制条；公共面板默认覆盖，用户固定后在剩余画墙宽度至少 960px 时侧停靠 |
| 768～1279px | 适合 iPad 横屏/中等桌面窗口；360px 左右侧覆盖面板；控制条优先保留核心动作 |
| <768px | 紧凑顶栏；底部两行控制条；房间/设置使用底部面板或全宽面板；输入/列表优先保证可滚动空间 |

设计初值：面板宽 320～360px，触控菜单行高 48～52px，按钮间距至少 8px，表单文字 16px。具体断点由真实控件宽度验证，不按某一型号 iPad 固定。

触控存在时使用至少 44px 的命中区，核心按钮用 48px；桌面紧凑控件为 36～40px。采用 `any-pointer: coarse` 等能力信息决定舒适密度，`event.pointerType` 仅决定本次可用快捷方式。输入设备变化不重建播放器或重置操作对象。

页面使用动态视口与安全区域；软键盘出现时结合 VisualViewport（可用时）调整面板可视区。普通列表保留浏览器纵向滚动与缩放，局部交互捕获不扩展到整个页面。

视觉采用低干扰深色监看台：画墙保持黑底与直角无缝视频，外壳使用深灰蓝分区；浅蓝表示当前操作，绿色表示播放正常，琥珀表示等待/重连，红色用于失败及移除。图标搭配短文字，避免只靠颜色解释状态。面板正文约 14px、输入框 16px，主播名在小窗中精简显示，完整信息进入固定操作区。

## 7. iPad 能力与真实可用性

| 能力 | UI 与实现要求 |
| --- | --- |
| 开始播放 | 保留默认静音与恢复询问；播放受阻时在对应房间显示可直接点击的“播放”，不自动反复重试权限 |
| 声音 | 当前代码通过 video.muted / video.volume 控制。iPad Safari/Stay 的实际音量效果需要真机检查；无法实现逐路增益的环境显示静音、仅听及系统音量说明，不展示无效百分比 |
| 弹幕画中画 | 当前只实现 Document Picture-in-Picture。按真实能力展示；系统视频画中画若后续接入，需单列为不含弹幕的另一种能力 |
| 全屏 | 检测可用 API 并处理 Promise 拒绝；无系统全屏能力时可提供页面内专注观看，明确命名并保证可返回 |
| FLV/MSE 播放 | 现有播放链依赖 mpegts.js 的 mseLivePlayback。开始前检查并显示可恢复状态；不支持时提供已有“打开原直播间”路径，不假设改好触控即可播放 |

音频解除静音、全屏、画中画等需要用户激活的调用直接从真实点击处理链发起，避免先经过异步请求再调用。共享命令层不能统一把所有动作延后排队。

同时区分“最多添加 16 个房间”与“同时播放额度”：沿用用户已有的调度上限，在顶栏说明正在播放、正在连接及等待额度的数量。真机性能验证后再决定 iPad 的推荐播放上限和画质，不承诺 16 路高画质同时解码。打开面板和选择房间不自动停止或重新取流；状态刷新合并到动画帧，弹幕列表保留数量上限与批量更新。

## 8. 房间管理与状态反馈

- 房间库顶部显示已添加数量与上限；选择跨搜索/页签保留，沿用现有添加逻辑。底部固定显示“已选 N 个”和“添加 N 个”。
- 已添加列表负责排序、替换、单房移除和批量管理；“替换 A”始终展示目标，不混入普通添加流程。
- 播放/连接/排队分别计数。画格保留直播状态，当前房间控制条区分“直播中但本地暂停”“未开播”“正在重连”。
- 正在连接显示简短阶段；冷却中显示剩余等待，重试入口尊重已有冷却逻辑。错误不只用颜色表示。
- 单房移除位于更多，建议提供短时撤销；撤销恢复房间及设置并重新取流，不承诺恢复已经释放的原播放器连接。批量清空和退出继续明确确认影响。
- 空墙提供“添加房间”“加载上次房间”；加载、成功、空结果、失败都有对应反馈，失败保留用户选择和输入。

## 9. 代码落地路线与伪代码

继续使用当前原生 JS/ESM、ctx 模式及桌面/Stay 双构建，样式随单文件产物内嵌到 Shadow DOM。新增组件可按项目要求使用构建期 Tailwind 工具类，核心布局坐标仍由统一算法计算。

| 模块 | 调整 |
| --- | --- |
| `ui/shell-markup.js` | 简化顶栏，增加固定房间控制条、统一面板宿主与关闭入口 |
| `ui/tile-markup.js` | 减少小窗内控件；保留图层、状态、媒体和错误反馈 |
| `app/tile-events.js` | 单击选择；触屏不用双击放大；交互状态取消与去重 |
| 新 `app/room-controls.js`、`app/room-commands.js` | 渲染当前对象；统一快捷按钮、菜单和控制条的命令入口 |
| `app/audio.js`、`app/tile-audio.js` | 分离仅听对象、静音与音量调节，保留原声音偏好 |
| `app/tile-drag.js` | 限制拖动来源，增加点击换位状态与取消 |
| `app/drawer.js`、`app/tile-danmaku.js` | 公共面板与单房/全局作用范围；弹幕列表移出视频画格 |
| `core/tile-scale.js` | 依据空间减少入口，触控控件命中区不随视频缩小 |
| `app/persistence.js`、`core/workspace.js` | 新 UI 偏好和仅听目标的兼容读取、校验及持久化 |

```text
初始化：读取并校验工作区 → 探测输入与媒体能力 → 渲染界面
读取实际容器宽度 → 决定顶栏、控制条、面板形态
轻点房间 → 更新 selectedId → 渲染固定控制条（不改变声音和放大状态）
激活按钮 → 固定 roomId 与命令类型 → 校验房间仍存在、能力可用
  媒体敏感动作：在当前用户点击链中立即调用相应能力
  放大：ctx.setFocus → 现有综合均衡算法 → 更新原节点坐标
  声音：更新独立声音状态 → ctx.applyAudioAll
  仅改面板：更新 UI 状态，不触发取流与播放器重建
进入换位 → 选择源和目标 → ctx.swapTiles → 退出换位；取消不交换
关闭面板 → 消费当前交互 → 恢复触发按钮焦点，避免点击穿透
```

没有新增后端接口或数据库。仍使用现有 GM/storage 工作区；UI 密度等偏好可作为可选字段加入。仅听目标持久化使用稳定房号（例如 audio.soloRid），运行时映射为 tile.id，旧数据缺少时使用兼容默认值；旧的 selectedId 不作为新的听音对象依据。

实施顺序：先统一命令与三类房间状态，再实现固定控制条和可点击换位，然后迁移公共面板，最后处理触控命中区、能力降级和双端回归。

## 10. 验收场景

1. 桌面 1440/1920、iPad 横竖屏和约 600px 分屏均能完成添加、放大、静音、仅听、调音量、换位、替换和关闭面板。
2. 16 房小窗仍可轻点选中，通过固定控制条完成操作；按钮不缩成小于设计命中区的图标。
3. 全程不依赖右键、双击、悬停或拖动，也能完成全部核心功能。
4. 仅听 A 时选择或放大 B，默认出声对象仍为 A；打开“声音跟随大窗”后按明确规则切换。
5. 拖动滑杆、滚动列表和关闭遮罩不选择/放大背景房间，也不触发换位。
6. 弹幕面板不挤压单个视频画格；侧停靠时整体画墙重算，视频保持源比例。
7. 横竖屏、软键盘和鼠标/触控混用后，打开的面板、房间身份与视频节点保持一致。
8. 加载、空结果、失败、自动播放受阻、额度不足和设备能力缺失均有明确状态与可执行入口。
9. 模态表单有焦点约束及明确关闭按钮，菜单/面板关闭后焦点回到合理位置。
10. `yarn build`、`yarn test`、产物冒烟与桌面/Stay 语法检查通过；另外使用真实 iPad Safari + Stay 验证播放、声音、全屏、滚动和触控，不以桌面设备模拟替代。

- [W3C：Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)：44×44 CSSpx 的增强级目标，本方案将其作为触控设计基线，不声称这是所有场景的 AA 最低要求。
- [W3C：Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)：拖动功能需要无需拖动的单指针替代方式。
- [W3C：Media Queries Level 4](https://www.w3.org/TR/mediaqueries-4/#pointer)：primary pointer 与 any-pointer 的区别，适用于混合输入设备判断。
- [WebKit：New Video Policies for iOS](https://webkit.org/blog/6784/new-video-policies-for-ios/)：媒体用户激活、静音播放和 play() 拒绝等设计依据；具体系统版本仍需真机验证。
