# 全屏与主播搜索修复

检查日期：2026-10-17。本次发布同时包含尚未发布的可行主窗自动切换修复。

## 问题与依据

1. 画格位于 Shadow DOM 中，原实现只比较 `document.fullscreenElement === root`。标准规定文档的全屏元素会按树边界重定向，可能返回宿主而非画格，因而再次点击不能正确退出。原实现的 `try / catch` 也没有等待请求 Promise，无法捕获异步拒绝，且未监听浏览器主动退出。
2. 原搜索使用 `getSearchRecV2`。核对官网公开搜索代码，该接口用于输入联想；正式“用户”搜索使用 `searchUser`，`filterType=1` 代表主播，列表位于 `data.relateUser[].anchorInfo`，默认每页 28 项。使用联想结果代替正式搜索会漏掉较后的主播。
3. 原输入仅在 Enter 后查询，并会把数字/链接直接添加。改为停输后自动搜索时，必须同时取消旧请求、处理中文组词，并取消直接添加，避免输入中误加房间。

公开依据：

- [Fullscreen 标准：fullscreenElement 与树重定向](https://fullscreen.spec.whatwg.org/#dom-document-fullscreenelement)
- [斗鱼官网搜索页面](https://www.douyu.com/search?kw=%E9%98%BF%E9%A3%9E)
- [检查时官网公开搜索脚本](https://shark2.douyucdn.cn/front-publish/douyu-web-master/_next/static/chunks/app/search/page-8a42840e3dae131d.js)：`eG` 使用联想接口；用户搜索 store 使用 `searchUser`、`page`、`pageSize`、`filterType`；枚举模块 `73142` 将主播映射为 `1`。

## 实施规则和数据流

```text
点击全屏按钮或更多菜单代理
→ 同步调用标准 / WebKit 请求，保留用户激活
→ 等待结果并捕获异常；操作期间防止重复请求
→ fullscreenchange / webkitfullscreenchange
→ 读取实际树内全屏元素，兼容旧 WebKit 原生伪类
→ 同步进入/退出按钮、工具条与画格状态，调度原布局恢复
→ 迁入/迁出画中画重新绑定文档；关闭监控室/移除画格退出全屏

输入变化
→ 立即取消旧定时器、请求和状态探测，递增请求代次
→ 中文组词期间等待；上屏后重新计时
→ 停输 500ms
→ 数字/链接：精确房间探测；主播名：正式主播搜索第 1 页
→ 校验请求代次与取消信号
→ 按官方顺序显示有效主播，勾选与添加由用户显式执行
→ 加载更多：请求下一页、追加去重、保留跨页选择
```

搜索请求为 `GET /japi/search/api/searchUser?kw=...&page=1&pageSize=28&filterType=1`，保留官网返回顺序和未开播主播，不把 UP 主、创作者或分类推荐当作直播间。搜索范围对应官网“用户 → 主播”，不包含视频、鱼吧等综合搜索内容。平台验证/网络失败显示错误及重试，不冒充空结果。

没有新后端、数据库迁移或持久化字段；分页、请求代次和全屏状态只存在于运行时。

## 验证

- 全屏：Shadow DOM / 普通 DOM、标准 / WebKit API、连续进退、浏览器主动退出、异步失败、重复点击、跨文档迁移和原布局尺寸保留。
- 搜索：官网接口参数、单字搜索、类型筛选、真实房间身份、分页、中文输入、停输时机、请求取消、迟到响应、跨页选择、失败重试和数字输入不自动添加。
- 真实浏览器：本地测试墙调用产品模块及浏览器原生全屏 API，两个房间均可进入/退出，退出后恢复原画格尺寸；固定搜索数据验证自动查询、加载更多及选择保留。
- 公开接口实测：关键词“阿飞”的正式接口返回主播阿飞（84452）、你的阿飞ovo（114657）等主播，字段与官网公开实现一致。
- Stay 版执行构建、语法检查及前缀分支回归；当前环境未进行 iPad 真机测试。
